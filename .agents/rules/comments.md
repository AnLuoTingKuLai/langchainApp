# 备注与注释规则

> 用户级全局规则中若存在内容重复或冲突的注释规则，在本项目内一律以本文件为准。

## 目标（优先于「少写注释」）

- **完整可阅读性**：新人或半年后的自己，不逐行推演也能理解文件职责、数据流和关键业务决策。
- **人类扫读友好**：备注和空行要帮助人快速分辨字段块、条件分支、状态角色和数据来源；不能只做到“细读后能懂”。
- 注释补充代码**说不清**的部分：为什么这样做、边界条件、与接口/产品的对应关系。
- **禁止**用注释替代清晰命名；也**禁止**为了「代码自解释」而几乎不写注释。

## 基本原则

- 注释解释意图、约束和不明显的业务规则，不复述代码表面行为。
- 不写空泛注释（如「处理数据」「点击事件」「定义变量」）。
- 不留 TODO、临时说明或调试备注。
- 注释使用简体中文；API 名、类型名、专有名词保持原文。
- 修改代码时同步更新注释；删除代码时一并删除废弃注释。

## 必写注释（默认都要写，除非该块确实 trivial）

`.vue` 文件须同时覆盖 **`<script>` 分区备注** 与 **`<template>` 模块备注**，二者缺一视为未完成注释。

### 1. 文件头（每个 `.vue` / 业务 `.ts` 文件）

在首个 `import` 之前写块注释，说明：

- 文件职责（这个模块解决什么问题）
- 主要对外接口（props / emit / export 函数）
- 关键依赖或约束（权限、特殊接口兼容等，有则写）

```ts
/**
 * 影片编辑弹窗：新增/编辑影片基本信息、海报剧照与演职人员。
 */
```

### 2. 逻辑分区（`<script setup>` / 较长 `.ts`）

用分区标题注释把代码分成可扫读的块，**至少**包含：

| 分区 | 典型内容 |
|------|----------|
| 类型定义 | interface、类型别名 |
| Props / Emits | 组件契约 |
| 状态 | ref、reactive、computed |
| 常量 / 配置 | 列配置、选项列表、校验规则 |
| 数据加载 / 提交 | API 调用、表单序列化 |
| 事件处理 | 用户交互、弹窗子组件回调 |
| 生命周期 / 监听 | onMounted、watch |

```ts
// ====== 类型定义 ======

// ====== Props / Emits ======

// ====== 状态 ======

// ====== 常量 / 列配置 ======

// ====== 数据加载与提交 ======

// ====== 事件处理 ======
```

### 3. 导出函数与组合式函数

公共函数、工具函数、`useXxx` 组合式函数使用 JSDoc，至少说明：

- 做什么
- 参数含义与可选约束
- 返回值
- 副作用或调用前提（如需先登录、需传入 id 等）

### 4. 非平凡业务逻辑与函数内备注

**块级「为什么」说明**：以下情况在对应代码**上方**写 1～3 行，写清「为什么」：

- 业务规则不直观，单看代码无法理解决策原因
- 存在平台、权限、路由、缓存等特殊约束
- 为兼容历史接口或第三方行为做的非显而易见处理
- 复杂计算、状态机、权限判断、数据转换（说明输入输出关系）
- 有魔法数字、枚举映射、默认值背后的产品规则

**函数内字段说明**：关键逻辑块、局部变量、参数解构字段、组装对象属性，用单行 `//` 写在对应语句**上方**补一句说明（统一用上行备注，不用行尾注释）。

**状态定义说明**：连续定义 `ref` / `reactive` / `computed` / `defineModel` 等状态时，不能只依赖变量名。以下状态必须在上方说明其业务角色：

- `loading` / `saving` / `hydrating` / `initializing` 等流程控制状态：说明阻止什么操作、保护哪段流程。
- `visible` 代理、当前 id、当前编辑上下文、选中项、展开状态等 UI 状态：说明由谁驱动、影响哪个弹窗/列表/分支。
- 模式判断类 `computed`（如新增/编辑、是否已有客户、是否贸易型、是否展示账号）：说明决定哪些字段展示、校验或提交行为。
- 表单与组件桥接状态（如接口字段可选但子组件要求数组）：说明为什么需要稳定结构，避免误认为是无意义转换。

**连续状态赋值**（目的是降低新人介入成本）：连续为多组 `ref` / `reactive` 字段赋值以驱动同一业务场景时（如打开弹窗/抽屉、切换编辑模式、切换 Tab、选中详情、重置筛选等），角色不明显的字段须在赋值语句上方注明该字段在此场景下的业务角色；`null` / 空值清空项要说明「为何清空、避免与哪类模式串用」。命名完全自解释的字段（如重置筛选时的逐项清空）可用一条块级总述覆盖，不必逐行复述。若赋值顺序影响行为（如先就绪再打开弹层，避免 props 闪烁），在顺序敏感处说明一次即可，不要求每个 `visible = true` 都写。

```ts
// 添加子菜单
const onAddSubMenu = (parent: MenuConfigItem) => {
  // 子菜单新增模式，表单锁定父级与层级
  addModalMode.value = 'menu-sub';
  // 父级节点，用于预填 parentMenuId 与校验层级上限
  addModalParentMenu.value = parent;
  // 非编辑菜单，清空编辑目标，避免与编辑模式串用
  addModalEditingMenu.value = null;
  // 状态就绪后再打开弹窗，避免 props 闪烁
  addModalVisible.value = true;
};
```

### 5. Vue 模板（必写）

`<template>` 与 `<script>` 同等要求：**每个逻辑模块开头必须有 HTML 注释**，模块与模块之间用备注分隔，扫一眼能看懂页面结构与业务分区。

#### 5.1 路由页面模块总述（必写）

每个路由模块入口 `src/views/**/index.vue` 的 `<template>` **最顶部第一行**必须写一条模块用途备注，标明「这个页面模块是干嘛的」。

- **适用范围**：路由页面入口 `index.vue`（`src/views` 下挂到路由的页面）；子组件不强制本条，但仍需遵守下文分区备注。
- **位置**：紧跟 `<template>` 之后、任何实际 DOM / 组件之前；不得被其他备注或空行挤到后面。
- **写法**：HTML 注释；内容用简短中文模块名即可（通常与菜单/路由中文名一致，可对照 `src/views/index.md`）。
- **禁止**：空泛词（如「页面」「列表页」）；禁止用 `/* ... */`（template 内无效，必须用 `<!-- -->`）。

```html
<template>
  <!-- 合同管理 -->
  <MqMainContent>
    ...
  </MqMainContent>
</template>
```

#### 5.2 模板内逻辑分区备注

**什么算「模块」**（满足任一即需单独备注）：

| 模块类型 | 示例 |
|----------|------|
| 布局插槽区块 | `#top`、`#extra`、`#footer` |
| 页面主区域 | 筛选区、表格区、详情区、左右分栏 |
| 独立业务区块 | 统计条、提示条、工具栏、表单分组 |
| 弹窗 / 抽屉挂载点 | 与主内容并列的 `v-model:visible` 组件 |
| 条件分支根节点 | `v-if` / `v-else` 各代表一块独立 UI |

**字段级模板备注（必须写）**：

连续出现的字段、表单项、只读描述项、配置组件或条件分支，必须按业务字段块补 HTML 注释，并用空行分隔。尤其包括：

- `<a-descriptions-item>` 连续展示详情字段时：说明字段来源、展示优先级、空值兜底或条件展示原因。
- `<a-form-item>` 连续维护表单字段时：说明字段业务含义、是否锁定、是否影响其他字段/接口匹配/提交校验。
- 业务组件分支（如返佣配置、折扣配置、附件列表、开票规则、影院分组）：说明何时展示、传入的关键数据、事件流向。
- 插槽（如 `#barLeft`、`#operation`、表格自定义列）：说明这个插槽承载的业务操作或字段展示规则。

示例：

```html
<!-- 资金通道：接口名称优先，名称缺失时展示接口编码 -->
<a-descriptions-item label="资金通道">...</a-descriptions-item>

<!-- 对公账号：仅贸易型展示，平台型不维护该字段 -->
<a-descriptions-item v-if="isTradeType" label="对公账号">...</a-descriptions-item>

<!-- 税率：直接展示接口 taxRate，不做本地格式转换 -->
<a-descriptions-item label="税率">...</a-descriptions-item>
```

**写法要求**：

- 备注写**业务含义 + 关键交互**，不写「表单区域」「按钮区」等空泛词。
- 相邻模块之间**各写一条**；嵌套子模块在子块开头再补一条。
- 备注与对应字段块之间保持清晰视觉层级；相邻字段块之间用空行分隔，避免注释和代码挤成一团。
- 路由页面入口须先满足 §5.1 的模块总述；其后再写各逻辑分区备注。非路由子组件若仅有一个根容器、无分区，也至少在 `<template>` 下第一行写一条总述备注。

```html
<template>
  <!-- 菜单配置 -->
  <!-- 页头：副标题与启停统计 -->
  <template #top>
    <!-- 操作说明：仅启用项在全平台可见 -->
    <a-alert type="warning">...</a-alert>
  </template>

  <!-- 主内容：左侧菜单树 + 右侧详情 -->
  <div class="menuConfigPage">
    ...
  </div>

  <!-- 弹层：新增/编辑菜单与操作按钮 -->
  <template #extra>
    <!-- 添加菜单弹窗 -->
    <MenuAddModal ... />
  </template>
</template>
```

## 什么时候可以少写

- 单行 getter/setter、一行转发调用、命名已完全表达意图的 trivial 代码。
- 与分区标题重复的逐行注释（不要写「// 表单引用」在 `const formRef = ref()` 上方）。
- 函数内命名已自解释、且无业务歧义的简单局部变量。
- **例外**：模板中的连续业务字段、条件分支组件和状态定义区，不因命名看似清楚而省略备注；这些位置优先满足“扫读友好”。
- **例外**：连续为多组状态赋值以驱动同一业务场景时，角色不明显的字段与清空项不适用「少写」——见 §4。

## 禁止事项

- 用注释掩盖过长函数、混乱命名或职责不清（应优先重构或补分区标题）。
- 写与代码不一致的历史描述。
- 机械地为每一行代码加注释（§4 要求备注的连续状态赋值场景除外）。

## 格式

- 分区标题、简短说明：单行 `//` 或 `// ====== 标题 ======`。
- 文件头、导出函数：块注释 `/** ... */`（JSDoc）。
- 路由页面 `index.vue` 模块总述：`<template>` 第一行 `<!-- 模块中文名 -->`（见 §5.1）。
- 模板分区/字段：HTML 注释 `<!-- 业务含义：关键字段或交互 -->`；位置与分隔要求见 §5.2，不在此重复。
- 字段级模板备注：写在字段块上方，字段块之间保留空行；不要把多个字段的说明挤在一行或贴在同一段里。
- 接口字段展示备注：涉及接口字段、枚举兜底、格式化或只读展示时，写清「接口字段优先 / 本地枚举兜底 / 不做本地转换 / 条件展示原因」。
- 配置型常量命名见 `format.md`（全大写下划线）；常量上方可一句话说明用途。

## 自检清单（写完代码后对照）

- [ ] 文件头能回答「这是谁、干什么、对外暴露什么」
- [ ] script 内有清晰分区，扫一眼能找到状态 / API / 事件处理
- [ ] 状态定义区已说明 loading、visible、当前上下文、模式判断等状态的业务角色
- [ ] 路由页面 `index.vue` 的 `<template>` 第一行已写模块用途总述（如 `<!-- 合同管理 -->`）
- [ ] template 内每个逻辑模块有 HTML 备注，模块与模块之间已分隔标注
- [ ] template 内连续字段、表单项、条件组件分支已有字段级备注，并用空行形成视觉分组
- [ ] 每个 export / useXxx / 复杂函数有 JSDoc 或等效块注释
- [ ] 函数内关键逻辑与字段含义已说明（含连续状态赋值中角色不明显字段与清空项的备注）
- [ ] 非显而易见的业务分支都有「原因」说明
- [ ] 涉及接口展示的字段已写清字段来源、展示优先级、枚举兜底或不转换原因
- [ ] 没有空泛注释、TODO、与代码矛盾的旧注释
