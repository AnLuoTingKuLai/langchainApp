# Git 规则

## 基本原则

- 不自动提交 Git，除非用户明确要求。
- 不执行 `git reset --hard`、`git checkout --` 等会丢弃变更的命令，除非用户明确要求。
- 工作区存在用户改动时，不回滚、不覆盖、不合并处理无关变更。
- 修改前后可以查看 `git status --short`，用于识别变更范围。
- 不擅自切换分支、拉取远程分支、推送远程分支或执行合并。

## 提交消息格式

提交消息使用 Conventional Commits：

```text
<type>(<scope>): <subject>
```

- `type` 必填，使用下方类型表。
- `scope` 可选，用于说明影响模块，例如 `router`、`store`、`login`、`layout`。
- `subject` 必填，使用简短中文描述，不超过 50 个字符。
- 标题末尾不加句号。

示例：

```text
feat(login): 新增验证码登录
fix(router): 修复权限路由跳转异常
docs: 完善 Git 规则说明
```

## type 类型表

| 类型 | 含义说明 |
| --- | --- |
| `feat` | 新增功能 |
| `fix` | 修复 bug |
| `docs` | 仅修改文档，如 README、规则文件 |
| `style` | 修改代码格式，不影响功能，例如空格、缩进、分号 |
| `refactor` | 代码重构，不影响功能和外观 |
| `perf` | 性能优化 |
| `test` | 添加或修改测试代码 |
| `chore` | 构建过程或辅助工具变更 |
| `ci` | CI 配置、脚本等变动 |
| `revert` | 回滚 commit |

## 提交要求

- 用户要求提交时，先确认变更范围。
- 只暂存本次任务相关文件，不把无关改动一起提交。
- 如果本次变更只修改规则或说明文档，优先使用 `docs`。
- 如果 lint 自动修改了文件，提交前要重新确认 diff。

## 分支与协作

- 不擅自创建、删除或重命名分支。
- 不擅自修改远程地址或 Git 配置。
- 发现当前分支或工作区状态会影响任务时，先说明风险再继续。
