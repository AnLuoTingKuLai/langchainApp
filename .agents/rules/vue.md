# Vue 3 开发规则

## 组件

- 组件优先使用 `<script setup lang="ts">`，避免 Options API；新代码统一 TypeScript。
- 组件职责单一，逻辑复杂时抽组合式函数。
- 模板保持简洁，复杂条件/过滤/格式化放计算属性或函数。
- Props / Emits 的类型声明、默认值与 `v-model` 约定遵循 `format.md` 的「Props 与事件」。

## 响应式

- `ref` 用于基础值和需要整体替换的引用；`reactive` 仅用于属性稳定的复杂对象。
- `computed` 表达派生状态，不用 watcher 做同步计算。
- `watch` 只处理副作用，例如请求、缓存、外部事件同步。
- 解构 reactive 对象用 `toRefs`。
- 生命周期钩子只放与生命周期强相关的逻辑，业务流程拆到函数或组合式函数。

## 组合式函数

- 可复用逻辑抽成 `useXxx` 组合式函数。
- 组合式函数要暴露清晰输入和输出，不直接依赖页面内部变量。
- 涉及副作用的组合式函数要在内部处理清理逻辑，例如事件监听、定时器、订阅。
- 不新增 mixin；旧 mixin 只在明确需要改造时再迁移。

## TypeScript

- 若文件使用 TypeScript：页面、组件、组合式函数都要保持明确类型，不用隐式 `any` 糊过去。
- 优先使用 `interface` 描述对象结构；简单联合类型、字面量类型可使用 `type`。
- `ref` 初始值不能准确推断时，显式写出类型；组件实例、DOM 引用、定时器等容易推断错的值必须显式标注。
- 共享类型放在对应模块附近；跨模块复用时再提取到模块 `types.ts`。
- 善用类型推断，不过度注解。

## 路由

- 路由级组件可用 `() => import('...')` 懒加载。
- 参数用 `useRoute` 获取，跳转用 `useRouter`。

## API 与数据

- 请求参数、响应数据尽量有清晰类型或 JSDoc。
- 不在页面里直接拼复杂请求结构，优先放到 API 模块或工具函数。
- 后端字段如果命名不符合前端规范，只在接口边界处理，业务层尽量使用清晰命名。

## 性能与模板

- v-show 用于频繁切换，v-if 用于条件渲染。
- 列表必加 `key`，不要用 index。

## 表单

- v-model 绑定响应式数据；校验规则遵循 `format.md`「表单校验规则」。
- 提交时显示 loading，错误信息回显到字段。
