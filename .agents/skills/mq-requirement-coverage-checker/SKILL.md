# 需求覆盖度分析

## 唤起关键词

`检查覆盖度` / `对照需求看看做的对不对` / `哪些没实现` / `对需求` / `需求覆盖度`

## 何时使用

用户已有需求文档（PRD / 功能列表 / 原型说明等），且已有对应静态页面（常来自 `mq-prototype-to-arco-vue`），要求核对是否一致。

## 范围边界（务必遵守）

本 skill **只校验静态页面**，对照需求看 UI / 文案 / 字段 / 控件 / 弹窗 / 前端交互流程是否齐备。

### 要核对（静态）

- 页面 / 模块 / Tab / 分区是否存在
- 表单项、表格列、筛选项、展示字段是否齐全，文案与需求是否一致
- 按钮、入口、弹窗、抽屉、步骤条等控件是否存在
- 纯前端交互：显隐、禁用、必填提示文案、确认框、跳转入口是否按需求出现
- 布局与交互流程在静态层面是否对得上需求描述

### 一律忽略（接口及相关逻辑）

以下内容**不做覆盖度判定**，即使需求文档写了也不要据此判「部分覆盖 / 未覆盖」：

- 是否调用真实接口、是否联通、是否已接 Apifox / 后端
- 请求方法、路径、入参、出参、分页、鉴权、错误码
- Mock 数据真假、列表数据是否来自接口、提交是否真正落库
- 接口层校验、后端业务规则、金额/库存等依赖接口的数据正确性
- `api` 目录、请求封装、loading/空态是否绑定真实接口返回

需求点若本质是数据 / 接口类（如「金额从 XX 接口读取并校验」「保存后调创建接口」）→ 记为 **未涉及（数据交互）**，**不进入下面三张覆盖度表**，可在报告末尾用简短列表单列，勿强行判定覆盖或不覆盖。

核对时若页面用本地 mock / 写死数据撑起了字段与交互，只要静态结构齐备，仍可判为完全覆盖或按静态差异判部分覆盖——**不得因「没接真接口」扣分**。

## 执行步骤

1. **拆解需求**：拆成可核对的需求点并编号。优先复用文档原编号（如 `3.3.1-1`）；否则用 `R-01`、`R-02`…
2. **先剔除接口类**：凡属「一律忽略」的需求点直接归入未涉及，不进入三张表。
3. **逐条核对静态页面**：剩余每条只归入下列三类之一：
   - **完全覆盖**：字段 / 交互 / 规则在页面中都能找到，且静态逻辑一致。
   - **部分覆盖**：有相关实现，但缺静态细节（少校验提示、少状态、字段类型/位置不符等）。
   - **未覆盖**：页面中完全没有对应静态实现。
4. **按三类分别输出三张表**（强制，禁止合成一张大表）。
5. **不要改代码**：本 skill 只出报告；用户点名修改后再另开任务改页面。

## 输出格式（强制）

先给一行**汇总**（条数即可）：

```text
汇总：完全覆盖 N ｜ 部分覆盖 N ｜ 未覆盖 N ｜ 未涉及（数据交互） N
```

然后**固定按此顺序**输出三张 Markdown 表。表题即状态，表内**不要再写「覆盖状态」列**。

### 表 1：完全覆盖

| 编号 | 需求点 | 说明 |
|------|--------|------|
| … | … | 一致（或留空） |

### 表 2：部分覆盖

| 编号 | 需求点 | 差异点（必须具体，便于按编号改） |
|------|--------|----------------------------------|
| … | … | 例如：有客户选择，但缺少必填校验提示 |

### 表 3：未覆盖

| 编号 | 需求点 | 缺失说明（必须具体） |
|------|--------|----------------------|
| … | … | 例如：页面未见批量导入入口 |

### 空表与未涉及

- 某一类为 0 条时：仍保留该表标题，表体写一行 `| — | （无） | |`，不要省略整张表。
- 未涉及项（若有）放在三张表**之后**，用简短列表即可，例如：
  - `未涉及（数据交互）：3.3.2-4 金额需接口校验；…`

## 输出示例

```text
汇总：完全覆盖 1 ｜ 部分覆盖 1 ｜ 未覆盖 1 ｜ 未涉及（数据交互） 0
```

**完全覆盖**

| 编号 | 需求点 | 说明 |
|------|--------|------|
| 3.3.1-1 | 渠道列表需支持按渠道名称搜索 | 一致 |

**部分覆盖**

| 编号 | 需求点 | 差异点 |
|------|--------|--------|
| 3.3.1-2 | 渠道列表新增时需选择所属客户 | 已有客户选择，缺少必填校验提示 |

**未覆盖**

| 编号 | 需求点 | 缺失说明 |
|------|--------|----------|
| 3.3.4-1 | 渠道排期需支持批量导入 | 页面未见批量导入入口 |

用户后续可直接说：「按表 2 的 3.3.1-2、表 3 的 3.3.4-1 补上」。

## 与其他 skill 边界

| 诉求 | 去向 |
|------|------|
| 对照需求出三张**静态**覆盖度表（忽略接口） | **本 skill** |
| 按编号改页面 / 补切图 | `mq-prototype-to-arco-vue` 或普通改页任务 |
| 接真实接口 / 联调 / 入参出参 | `mq-apifox-interface-writer`（不在本 skill 评估范围内） |
